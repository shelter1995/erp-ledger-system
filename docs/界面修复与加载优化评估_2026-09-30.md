# 界面修复与加载优化评估

## 最终发布范围

- 四个业务页面统一筛选标题、输入框高度和间距，已验证 1440、1024、390 像素宽度。
- 全站顶栏用“数据最新修改”替代原本的浏览器加载时间。新接口 `/api/data/latest-modified` 只返回当前账号部门权限范围内的最新业务修改时间，不受首页筛选影响，无业务查看权限或无可见记录时返回空值。
- 时间显示到秒，按北京时间处理；首页日期筛选腾出空间，窄屏标题独占一行。
- 最终本地检查：前端 60 项、后端定向测试 7 项、类型检查、生产构建通过；浏览器虚构 API 验收覆盖页面切换、直接进入采购页、筛选独立性及三种窗口宽度。后端权限用例使用模拟连接，不能替代生产接口验证。
- 本次需要前后端共同发布，前端 r4 脚本不能部署新增接口。发布基线为服务器现有部门会话热修复镜像，保留该热修复；本轮不包含数据库迁移。

## 第二轮筛选反馈

- 基本信息移除单日“销售订单日期”筛选，只保留日期范围；录入表单中的订单日期不受影响。
- 采购筛选标题修正为“付款时间范围”，继续按付款期次日期筛选；销售页为“回款时间范围”。
- 四个在用页面共用 `ManagerFilter`，项目经理提示统一为“输入项目经理姓名”，历史负责人开关与标题同行、输入框在下方。基本信息新增该开关并支持历史匹配、组合筛选和重置。
- 客户单位、采购厂商等重复字段的输入提示统一为“输入客户单位名称”“输入采购厂商名称”。
- 本轮前端回归 60 项通过，类型检查与构建通过；服务器上第一轮发布成功由用户确认，第二轮修改尚未部署。

## 本轮范围

- 台账管理的“包含历史负责人”与项目经理输入框放在同一组。
- 日期选择框为空时统一显示“年 / 月 / 日”，保留原生日期选择及 ISO 日期值。
- 基本信息增加项目经理、部门筛选，查询与重置均接入现有筛选逻辑。
- 基本信息、销售、采购清单逐页显示；等待、失败和空结果分开呈现。销售、采购清单到达后立即显示，不再等待订单选项接口。切换页面后的旧请求不会覆盖新页面或继续取下一页。
- 数量展示统一为两位小数；原始数值、编辑值和计算精度保持不变。

用户反馈的“无筛选也暂无记录”在旧代码中可能由等待全量加载造成：`App.tsx` 在 `loadAllPages` 完成前不设置清单；空数组会直接渲染“暂无符合条件”。销售、采购还通过 `Promise.all` 等待订单选项。这是已确认的前端缺陷，不能单独证明线上持续空清单的全部原因。若完成加载后仍为空，需要在实际账号会话中核对列表接口的状态码、`total`、`items.length` 和部门授权范围；不要记录令牌或原始业务明细，也不要用放宽权限来绕过问题。

## 下一轮性能改进

结论：可分阶段做，整体中等难度。以下工期是按当前代码结构估算的开发和回归时间，不是三年数据的实测结果。

| 项目 | 当前代码证据 | 难度与估算 |
| --- | --- | --- |
| 首屏服务端分页 | `loadAllPages.ts` 每次取 500 条并串行拉完；页面再用 `slice` 做本地分页；`App.tsx` 每次切换页面清空并重新加载 | 中等，约 2–3 人日；需同时迁移筛选、总数、跨页选择和汇总，避免只统计当前页 |
| 订单选项独立按需加载 | `/sales/order-options`、`/purchases/order-options` 无分页，查询 `v_order_line_finance` 全部可见明细 | 低至中，约 0.5–1 人日；改为搜索和按需查询，保留部门范围及编辑上下文 |
| 汇总 SQL 与索引 | `read_summary` 先取全部明细再用 Python 聚合；三个列表均有 COUNT、财务视图查询及历史补充查询 | 中等，约 1–3 人日；先测 COUNT/数据页/历史补充各耗时，再做 EXPLAIN，不能凭代码直接决定加索引 |
| 页面缓存与代码拆分 | 切页重新请求；生产构建主包约 560 KB，触发超过 500 KB 提示 | 低至中，约 0.5–1 人日；缓存需在修改、导入、权限变更、退出时失效 |

优先顺序：先采样实际耗时，再做服务端分页和订单选项按需加载，最后依据证据优化 SQL。首个可验收阶段预计约 3–5 人日。索引或汇总结构调整需要另行评估数据库迁移。

建议采集：三个页面首次进入、再次进入和筛选后的接口耗时、返回大小、数据库耗时与首条记录出现时间；同一账号、同一份脱敏数据做前后对比。验收必须覆盖跨年筛选、全量汇总、批量选择、部门权限及修改后刷新。

## 验证边界与手动检查

本轮使用前端回归、TypeScript 检查、生产构建，以及真实 Edge 浏览器配合虚构 API 响应验证。浏览器用例覆盖慢分页、经理/部门/日期筛选、重置、销售清单不等待选项、采购清单、台账开关位置、失败重试。没有对生产三年数据做性能测试，没有修改数据库、提交、推送或部署。

部署后请用原问题账号检查：

1. 基本信息无筛选进入，等待期间显示加载提示，随后显示记录；加载完成后不应仍错误地显示空记录。
2. 项目经理和部门单独、组合查询，再点击重置，核对记录恢复。
3. 切换销售、采购，核对清单；基本信息及详情中的数量为两位小数。
4. 台账中项目经理与历史负责人开关同组；空日期提示为中文，选定日期后查询正常。

如第 1 项仍失败，提供接口状态码和总条数即可继续定位；前端虚构数据验收不替代此项生产验证。
